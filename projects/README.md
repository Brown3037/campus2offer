# projects/ 项目拆解

一段项目经历，拆到能被面试官追问五层。

## 结构

```markdown
# 项目名（一句话说清楚解决了谁的什么问题）

## 问题与用户
## 系统边界（输入、输出、不做什么）
## 我负责的部分
## 关键设计：方案 A vs 方案 B，为什么选 A
## 评测：指标、基线、怎么测的
## 踩过的坑：现象 → 定位 → 修复 → 回归
## 如果重做
```

## 要求

- 至少有一个**可复现**的东西：仓库、脚本、压测数据、截图
- 数字写明口径（P95 还是平均、多少条数据、什么机器）
- 别写「使用 Spring Boot 完成了增删改查」，写取舍
